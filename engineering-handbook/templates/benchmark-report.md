# Competitive Benchmark Report

## Field instructions

| Field | How to complete it |
| --- | --- |
| Decision question | State the product decision the comparison informs. |
| Cohort and sources | Name comparable offerings and source types with collection dates. |
| Criteria and scoring | Define observable criteria, weighting, and scoring scale. |
| Findings | Separate observed capability from analyst interpretation. |
| Limitations | State unavailable data, version uncertainty, and non-comparable factors. |

## Completed example: Product Atlas

**Decision question:** Which onboarding gap should Atlas prioritize for mid-market retail customers?  
**Cohort and sources:** Atlas, StockPilot, DemandMesh, and SupplyMap; public guides and trial environments reviewed 2026-07-20 through 2026-07-30.  
**Criteria and scoring:** Five-point rubric for connector setup, data validation, time to first forecast, and operator diagnostics; equal weighting.  
**Findings:** Atlas scored 4 for connector setup because its warehouse examples covered common imports. Atlas scored 2 for data-quality diagnostics because trial users could see an error but not the affected record set.  
**Conclusion and limitations:** Product Atlas should test self-serve diagnostics. Trial access did not expose enterprise support workflows, so the report does not compare support quality.
